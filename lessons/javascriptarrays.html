 1. JS Arrays 

    
    
        
  1. Định nghĩa: array là object đặc biệt lưu danh sách giá trị có thứ tự, chỉ số bắt đầu từ 0, length tự cập nhật. Tạo bằng [ ... ], phần tử có thể khác kiểu. typeof của array là "object", nên kiểm tra bằng Array.isArray().
    2. 
        
  2. Khi nào dùng: danh sách cùng loại cần thứ tự hoặc cần lặp (sản phẩm, điểm số, bình luận); dữ liệu dạng danh sách từ API / JSON; xử lý hàng loạt phần tử.
    3. 
        
  3. Khi nào KHÔNG dùng: cần tra cứu theo khóa chữ thì dùng object / Map. Cần loại trùng, kiểm tra tồn tại nhanh thì dùng Set. Mỗi vị trí có ý nghĩa khác nhau (tên, tuổi, email) thì dùng object.
    4. 
        
  4. Tránh xung đột khi web lớn: array được gán theo tham chiếu (b = a không sao chép). Hàm nhận mảng từ nơi khác mà gọi push / sort / splice sẽ sửa luôn dữ liệu của họ, hãy copy bằng [...a] trước. Dữ liệu dùng chung nên gom vào một object riêng thay vì nhiều mảng global.

 2. JS Array Constructor 

    
    
        
  1. Định nghĩa: các cách tạo mảng: literal [], new Array(...), Array.of(...), Array.from(iterable, hàmBiếnĐổi), new Array(n).fill(x), spread [...x].
    2. 
        
  2. Khi nào dùng: [] là mặc định. Array.from({length: n}, fn) để tạo dãy số hoặc bảng. Array.from để đổi chuỗi / Set / NodeList thành mảng. Array.of khi cần mảng chỉ có một số.
    3. 
        
  3. Khi nào KHÔNG dùng: new Array(5) tạo 5 ô trống chứ không phải [5]. new Array(3).fill([]) cho 3 ô cùng trỏ vào một mảng. Không cần new Array(...) khi [] là đủ.
    4. 
        
  4. Tránh xung đột khi web lớn: new Array(5) và new Array(5, 6) hành xử khác nhau (độ dài hay danh sách), rất dễ gây lỗi khi tham số đến từ biến. fill với object / mảng làm mọi ô dùng chung tham chiếu, sửa một ô là đổi tất cả. Dùng Array.from kèm callback để mỗi ô là một object riêng.

 3. JS Array Methods 

    
    
        
  1. Định nghĩa: các method thao tác trên mảng: thêm / bớt ở đầu hoặc cuối (push, pop, shift, unshift), cắt và ghép (slice, splice, concat, flat), chuyển thành chuỗi (join). Chia hai nhóm: sửa mảng gốc (push, pop, shift, unshift, splice, sort, reverse, fill) và trả mảng mới (slice, concat, toSorted, toReversed, toSpliced, with).
    2. 
        
  2. Khi nào dùng: push / pop cho ngăn xếp; push / shift cho hàng đợi; slice để lấy một đoạn hoặc sao chép; splice để chèn / xóa ở giữa; join để ghép chuỗi.
    3. 
        
  3. Khi nào KHÔNG dùng: tránh shift / unshift trên mảng rất lớn (phải dịch cả mảng). Đừng nhầm slice (không sửa) với splice (sửa). Không dùng delete arr[i] (để lại ô trống), hãy dùng splice.
    4. 
        
  4. Tránh xung đột khi web lớn: luôn nhớ method nào sửa mảng gốc: mảng dùng chung bị đổi bất ngờ là lỗi khó tìm nhất. Khi quản lý state (React, Vue...) hãy dùng bản trả mảng mới. Mảng nhận từ bên ngoài thì copy trước khi sửa.

 4. JS Array Search 

    
    
        
  1. Định nghĩa: các cách tìm trong mảng: indexOf / lastIndexOf (vị trí, so sánh bằng ===), includes (có hay không), find / findIndex / findLast (theo điều kiện), filter (tất cả phần tử khớp), some / every (có ít nhất một / tất cả đều thỏa).
    2. 
        
  2. Khi nào dùng: includes cho giá trị đơn giản; find để tìm object theo điều kiện (ví dụ theo id); findIndex khi cần vị trí để sửa / xóa; filter khi cần nhiều kết quả; some / every để kiểm tra điều kiện.
    3. 
        
  3. Khi nào KHÔNG dùng: indexOf / includes không tìm được object theo "nội dung giống nhau" (chỉ so tham chiếu). Không dùng filter(...)[0] thay cho find. Tìm đi tìm lại trong mảng rất lớn thì chuyển sang Map / Set.
    4. 
        
  4. Tránh xung đột khi web lớn: indexOf trả về -1 khi không có (không phải false), nên if (arr.indexOf(x)) luôn sai. find trả về chính object trong mảng, sửa nó là sửa dữ liệu gốc. Kết quả find có thể là undefined, phải kiểm tra. Thống nhất kiểu của id ("5" khác 5).

 5. JS Array Sort 

    
    
        
  1. Định nghĩa: sort() sắp xếp tại chỗ và mặc định coi mọi phần tử là chuỗi (so theo mã Unicode). Truyền hàm so sánh để sắp xếp đúng: (a, b) => a - b cho số, a.localeCompare(b, "vi") cho chữ tiếng Việt. toSorted() trả mảng mới, reverse() đảo ngược.
    2. 
        
  2. Khi nào dùng: sắp xếp danh sách hiển thị (theo giá, tên, ngày), xếp hạng, tìm phần tử nhỏ nhất / lớn nhất theo tiêu chí.
    3. 
        
  3. Khi nào KHÔNG dùng: không gọi sort() không có hàm so sánh cho số ([10, 9, 100] ra 10, 100, 9). Không sắp xếp cả mảng chỉ để lấy max (dùng Math.max hoặc reduce). Không xáo trộn bằng sort(() => Math.random() - 0.5) vì kết quả không đều, hãy dùng thuật toán Fisher–Yates.
    4. 
        
  4. Tránh xung đột khi web lớn: sort() sửa mảng gốc, nên mảng dùng chung bị đổi thứ tự bất ngờ. Hãy dùng toSorted() hoặc [...a].sort(). Tiếng Việt cần localeCompare("vi") thì Ă, Â, Đ, Ổ mới xếp đúng. Phần tử undefined luôn bị đẩy xuống cuối.

 6. JS Array Iterations 

    
    
        
  1. Định nghĩa: các cách duyệt mảng: forEach (làm việc với từng phần tử, không trả về gì), map (biến đổi, trả mảng mới cùng độ dài), filter (lọc), reduce (gộp thành một giá trị), for...of (dễ đọc, dùng được break và await), entries() (lấy cả chỉ số).
    2. 
        
  2. Khi nào dùng: map để dựng danh sách hiển thị; filter rồi map nối tiếp nhau; reduce để tính tổng, đếm, nhóm; for...of khi cần dừng giữa chừng hoặc dùng await; forEach khi chỉ cần thực hiện hành động.
    3. 
        
  3. Khi nào KHÔNG dùng: không dùng map nếu bỏ phí kết quả (dùng forEach). Không dùng forEach với async/await vì nó không chờ. Không dùng for...in cho mảng. Không thêm / xóa phần tử trong lúc đang duyệt. reduce quá phức tạp thì viết vòng lặp rõ ràng hơn.
    4. 
        
  4. Tránh xung đột khi web lớn: callback sửa biến bên ngoài (tác dụng phụ) khiến kết quả khó đoán, hãy viết hàm thuần. reduce trên mảng rỗng mà không có giá trị khởi tạo sẽ ném lỗi. Arrow function dùng { } mà quên return thì map ra toàn undefined. forEach không dừng được bằng break.

 8. JS Array const 

    
    
        
  1. Định nghĩa: const ds = [...] khóa tham chiếu: không gán lại ds = ... được. Nhưng nội dung bên trong vẫn sửa tự do (push, pop, sort, ds[0] = ...).
    2. 
        
  2. Khi nào dùng: nên là mặc định cho mọi mảng, kể cả mảng cần thêm / bớt / sửa phần tử, vì thường bạn không cần gán lại cả mảng.
    3. 
        
  3. Khi nào KHÔNG dùng: đừng tưởng const làm mảng bất biến (muốn thế phải dùng Object.freeze, mà cũng chỉ khóa tầng ngoài). Đừng gán lại ds = [] để "reset" khi khai báo bằng const (lỗi), hãy dùng ds.length = 0 hoặc khai báo bằng let.
    4. 
        
  4. Tránh xung đột khi web lớn: mảng const dùng chung giữa các file vẫn bị file khác push vào. Khi export hãy trả bản sao hoặc freeze. ds.length = 0 xóa luôn dữ liệu của mọi nơi đang giữ cùng tham chiếu. const ở ngoài cùng trùng tên với biến ở thẻ <script> khác sẽ gây SyntaxError.
    5.
