JavaScript Scope

Mục lục: JS Scope | Code Blocks | Hoisting | var / let / const | Strict Mode

Hàm trợ giúp dùng chung (chayThu chạy một đoạn code dạng chuỗi trong hàm riêng để bắt lỗi mà không làm hỏng trang): 






 1. JS Scope 

    
    
        
  1. Định nghĩa: scope (phạm vi) là vùng code mà một biến hoặc hàm "nhìn thấy" được. Có 3 loại chính: global, function, block. Code bên trong nhìn ra scope bên ngoài được (scope chain), code bên ngoài không nhìn vào trong được.
    2. 
        
  2. Khi nào dùng: luôn có hiệu lực. Hãy tận dụng để giấu dữ liệu nội bộ trong hàm hoặc khối, chỉ để ở global những gì thực sự dùng chung.
    3. 
        
  3. Khi nào KHÔNG dùng: không tạo biến global cho dữ liệu chỉ dùng cục bộ. Không đặt biến local trùng tên biến bên ngoài (shadowing) khi không chủ ý.
    4. 
        
  4. Tránh xung đột khi web lớn: mọi thẻ <script> thường chung một global scope nên trùng tên là ghi đè nhau. var và function ở ngoài cùng còn thành thuộc tính của window. Quên khai báo thì tạo biến global ngầm. Hãy bọc code trong hàm / khối / module, hoặc gom dữ liệu chung vào một object.

 2. JS Code Blocks 

    
    
        
  1. Định nghĩa: code block là đoạn code nằm trong { }, gom nhiều statement thành một đơn vị (thân if, for, while, function, hoặc khối đứng riêng). let / const / class khai báo trong khối chỉ sống trong khối; var thì thoát ra ngoài.
    2. 
        
  2. Khi nào dùng: giới hạn tuổi thọ biến tạm (trong vòng lặp, if); bọc mỗi case của switch; tạo scope riêng cho một đoạn code mà không cần viết hàm.
    3. 
        
  3. Khi nào KHÔNG dùng: không dùng var trong khối mà mong nó bị nhốt lại. Khối đứng riêng quá nhiều làm code khó đọc, hãy tách thành hàm. Không bỏ { } ở if / for nhiều dòng.
    4. 
        
  4. Tránh xung đột khi web lớn: bỏ { } ở if rồi thêm dòng sau sẽ tạo lỗi logic âm thầm. Tên trong khối che tên bên ngoài dễ gây nhầm. Ở file không phải module, bọc code trong { } giúp các let / const không đè lên khai báo của file khác.
    5.

 3. JS Hoisting 

    
    
        
  1. Định nghĩa: hoisting là việc JS "kéo" phần khai báo lên đầu scope trước khi chạy code. Function declaration được kéo cả thân hàm; var được kéo và mang giá trị undefined; let / const / class cũng được kéo nhưng nằm trong "vùng chết" (TDZ) nên dùng trước là lỗi. Chỉ khai báo được kéo, phép gán thì không.
    2. 
        
  2. Khi nào dùng: chủ yếu là hiểu để đọc lỗi. Có thể tận dụng có chủ ý: đặt phần chạy chính ở trên, các hàm phụ (function declaration) ở dưới.
    3. 
        
  3. Khi nào KHÔNG dùng: không dựa vào hoisting của var để dùng biến trước khi khai báo. Function expression / arrow gán vào biến thì không gọi trước được. Hãy khai báo mọi thứ ở đầu scope.
    4. 
        
  4. Tránh xung đột khi web lớn: hai function declaration trùng tên (ở hai file) thì cái sau âm thầm ghi đè cái trước, không có lỗi nào cả. Dùng const + function expression, đặt tên duy nhất hoặc dùng module để tránh.
    5.

 4. JS var / let / const 

    
    
        
  1. Định nghĩa: ba từ khóa khai báo biến. var có phạm vi function, hoisted với undefined. let có phạm vi khối, gán lại được. const như let nhưng không gán lại được (object bên trong vẫn sửa được).
    2. 
        
  2. Khi nào dùng: mặc định dùng const; dùng let khi giá trị sẽ thay đổi; var chỉ khi bảo trì code cũ hoặc phải hỗ trợ trình duyệt rất cũ.
    3. 
        
  3. Khi nào KHÔNG dùng: không dùng var trong code mới. Không dùng let cho giá trị không đổi (dễ lỡ gán lại). Không nghĩ const là bất biến hoàn toàn.
    4. 
        
  4. Tránh xung đột khi web lớn: var ở ngoài cùng tạo thuộc tính trên window, có thể đè lên thuộc tính có sẵn của trình duyệt (name, status, top...). Trộn var và let cùng tên trong cùng scope là SyntaxError. Bật quy tắc ESLint no-var và prefer-const.

 5. JS Strict Mode 

    
    
        
  1. Định nghĩa: "use strict"; chuyển JS sang chế độ nghiêm ngặt: biến phải được khai báo, cấm một số cú pháp xấu, biến nhiều lỗi âm thầm thành lỗi thật, và this trong hàm thường là undefined. Đặt ở đầu file hoặc đầu hàm. class và module tự động là strict.
    2. 
        
  2. Khi nào dùng: mọi code mới; khi muốn bắt sớm lỗi gõ sai tên biến, ghi vào thuộc tính chỉ đọc, tham số trùng tên.
    3. 
        
  3. Khi nào KHÔNG dùng: "use strict" không nằm ở dòng đầu thì vô tác dụng. Đừng đặt ở đầu một file khi file đó được nối với nhiều script cũ chưa tương thích (nó biến cả file thành strict và làm hỏng code cũ).
    4. 
        
  4. Tránh xung đột khi web lớn: khi nối nhiều file lại thành một (bundle), "use strict" ở đầu có thể áp dụng sai phạm vi. Hãy đặt trong từng hàm / IIFE khi tích hợp code cũ, hoặc dùng module. Code cũ gán biến chưa khai báo, dùng with, số octal 010 sẽ lỗi khi bật strict.
