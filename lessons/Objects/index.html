JavaScript Objects

Hàm trợ giúp dùng chung. Dữ liệu của từng ví dụ nằm trong hàm hoặc object riêng để các ví dụ không giẫm lên nhau: 






 1. Object Definitions (Intro) 

    
    
        
  1. Định nghĩa: Object là tập hợp các cặp key: value (thuộc tính) mô tả một "thực thể" như người, xe, đơn hàng. Array, function, date... cũng là object.
    2. 
        
  2. Khi nào dùng: gom dữ liệu liên quan của một thực thể; truyền nhiều tham số cho gọn; lưu cấu hình; nhận dữ liệu JSON từ API.
    3. 
        
  3. Khi nào KHÔNG dùng: danh sách giá trị cùng loại, có thứ tự thì dùng array. Cần key bất kỳ, thêm / xóa liên tục, đếm số phần tử thì dùng Map. Chỉ một giá trị đơn thì dùng biến.
    4. 
        
  4. Tránh xung đột khi web lớn: object được gán theo tham chiếu: b = a không sao chép, sửa b là sửa a. Gom dữ liệu chung vào một object có tên riêng (namespace) thay vì nhiều biến toàn cục rời rạc.

 2. Object Properties 

    
    
        
  1. Định nghĩa: thuộc tính là cặp key-value của object. Truy cập bằng obj.key hoặc obj["key"]; thêm, sửa, xóa (delete), kiểm tra bằng in / Object.hasOwn.
    2. 
        
  2. Khi nào dùng: dấu chấm khi biết sẵn tên; ngoặc vuông khi tên nằm trong biến hoặc có khoảng trắng; ?. khi thuộc tính có thể không tồn tại.
    3. 
        
  3. Khi nào KHÔNG dùng: đừng đọc thuộc tính lồng sâu mà không kiểm tra (Cannot read properties of undefined); đừng delete phần tử của array.
    4. 
        
  4. Tránh xung đột khi web lớn: gõ sai tên thuộc tính không báo lỗi mà ra undefined, nên thống nhất quy ước tên key (camelCase). Thuộc tính có thể bị file khác thêm ngầm, hãy kiểm tra bằng Object.hasOwn.

 3. Object Methods 

    
    
        
  1. Định nghĩa: method là thuộc tính có giá trị là một function, gọi bằng obj.method(). Bên trong, this trỏ về chính object đó.
    2. 
        
  2. Khi nào dùng: hành vi gắn liền với dữ liệu của object: tính tổng, thêm vào giỏ, ghép họ tên, in thông tin.
    3. 
        
  3. Khi nào KHÔNG dùng: không viết method bằng arrow function (mất this); thiếu () thì nhận về cả function chứ không phải kết quả; logic không cần dữ liệu của object thì viết hàm riêng.
    4. 
        
  4. Tránh xung đột khi web lớn: đặt tên method rõ nghĩa, tránh trùng với method có sẵn (toString, valueOf). Method không nên sửa biến toàn cục. Tạo hàng nghìn object mà mỗi cái chứa bản method riêng thì tốn bộ nhớ, hãy đặt method vào prototype / class.

 4. Object this 

    
    
        
  1. Định nghĩa: this là "chủ nhân" của lời gọi hàm. Trong method, nó là object đứng trước dấu chấm. Hàm thường gọi một mình thì là window (hoặc undefined ở strict mode). Arrow function dùng this của nơi nó được viết.
    2. 
        
  2. Khi nào dùng: trong method và constructor để truy cập dữ liệu của chính object; dùng call / apply / bind khi cần chỉ định this.
    3. 
        
  3. Khi nào KHÔNG dùng: không dùng arrow function làm method; không truyền method làm callback mà không bind; hàm tiện ích độc lập không cần this.
    4. 
        
  4. Tránh xung đột khi web lớn: this phụ thuộc cách gọi, không phụ thuộc nơi viết. Tách method ra (const f = obj.method) là mất this. Dùng "use strict" để this không âm thầm trỏ vào window.

 5. Object Display 

    
    
        
  1. Định nghĩa: hiển thị object ra màn hình. In thẳng ra sẽ là [object Object], nên phải chuyển thành chuỗi bằng JSON.stringify, Object.values / entries, vòng lặp hoặc console.table.
    2. 
        
  2. Khi nào dùng: JSON.stringify để xem / lưu / gửi dữ liệu; console.table khi debug; template string khi hiển thị cho người dùng.
    3. 
        
  3. Khi nào KHÔNG dùng: không nối object vào chuỗi trực tiếp. JSON.stringify bỏ qua function, undefined, Symbol và báo lỗi với vòng tham chiếu. Không nhét dữ liệu người dùng vào innerHTML (XSS), hãy dùng textContent.
    4. 
        
  4. Tránh xung đột khi web lớn: gom cách hiển thị vào một hàm dùng chung (hienThi(obj)) thay vì mỗi nơi tự nối chuỗi một kiểu. Khi lưu / gửi dữ liệu, nhớ kiểm tra thứ gì bị mất sau stringify.

 6. Object Constructors 

    
    
        
  1. Định nghĩa: constructor function (hoặc class) là "khuôn" để tạo nhiều object cùng cấu trúc bằng new. Bên trong, this là object mới đang được tạo.
    2. 
        
  2. Khi nào dùng: cần nhiều object cùng loại (người dùng, sản phẩm, công việc) với cùng thuộc tính và method.
    3. 
        
  3. Khi nào KHÔNG dùng: chỉ cần một object duy nhất thì dùng object literal. Không gắn method vào từng object trong constructor khi tạo số lượng lớn, hãy dùng prototype / class.
    4. 
        
  4. Tránh xung đột khi web lớn: quên new thì this trỏ vào window và âm thầm tạo biến toàn cục. Dùng class (báo lỗi nếu quên new) hoặc "use strict". Tên constructor viết hoa, không trùng tên có sẵn (Date, Map, Event).

 7. Object Iterations 

    
    
        
  1. Định nghĩa: duyệt object là đi qua từng key / value bằng for...in, Object.keys(), Object.values(), Object.entries() (thường kết hợp for...of).
    2. 
        
  2. Khi nào dùng: in hoặc xử lý từng thuộc tính; tính tổng các giá trị; biến đổi cả object bằng Object.entries + map + Object.fromEntries.
    3. 
        
  3. Khi nào KHÔNG dùng: không dùng for...in cho array; không dựa vào thứ tự key dạng số (luôn xếp tăng dần trước); không thêm / xóa key trong lúc đang duyệt.
    4. 
        
  4. Tránh xung đột khi web lớn: for...in duyệt cả thuộc tính thừa kế. Nếu có file nào thêm gì đó vào Object.prototype, nó sẽ lọt vào mọi vòng lặp của cả trang. Dùng Object.keys / entries hoặc Object.hasOwn, và đừng bao giờ mở rộng Object.prototype.

 8. Object Get / Set 

    
    
        
  1. Định nghĩa: getter / setter (get, set) là thuộc tính "ảo": đọc và ghi như thuộc tính thường nhưng bên dưới thực sự chạy một hàm.
    2. 
        
  2. Khi nào dùng: thuộc tính tính ra từ thuộc tính khác (họ tên đầy đủ); kiểm tra / chuẩn hóa dữ liệu khi gán (tuổi hợp lệ, cắt khoảng trắng); thuộc tính chỉ đọc (chỉ có getter).
    3. 
        
  3. Khi nào KHÔNG dùng: getter không nên làm việc nặng hoặc có tác dụng phụ (gọi API). Setter không được ghi vào cùng tên chính nó (đệ quy vô hạn), hãy lưu vào _ten hoặc #ten. Thuộc tính đơn giản thì không cần.
    4. 
        
  4. Tránh xung đột khi web lớn: setter có thể ném lỗi khi dữ liệu sai nên chỗ gán phải có try/catch. Getter chạy lại mỗi lần đọc, nếu tính toán nặng hãy lưu cache. Getter trong object literal xuất hiện khi stringify, getter của class thì không.

 9. Object Management 

    
    
        
  1. Định nghĩa: các thao tác quản lý object: sao chép (spread {...a}, Object.assign, structuredClone), gộp, tạo từ prototype (Object.create), nhóm (Object.groupBy), kiểm tra (Object.hasOwn).
    2. 
        
  2. Khi nào dùng: sao chép trước khi sửa dữ liệu nhận từ nơi khác; gộp cấu hình mặc định với tùy chỉnh của người dùng; nhóm dữ liệu API theo loại.
    3. 
        
  3. Khi nào KHÔNG dùng: spread và assign chỉ sao chép nông, object lồng bên trong vẫn dùng chung. JSON.parse(JSON.stringify()) làm mất function / Date, nên ưu tiên structuredClone. Không so sánh object bằng == (chỉ so tham chiếu).
    4. 
        
  4. Tránh xung đột khi web lớn: sửa trực tiếp object nhận từ module khác là sửa dữ liệu của họ, hãy copy trước. Khi gộp, vế sau ghi đè vế trước. Đừng gộp dữ liệu người dùng vào object mà không lọc key (nguy cơ __proto__ pollution).

 10. Object Protection 

    
    
        
  1. Định nghĩa: các cách khóa object: Object.freeze (không thêm / sửa / xóa), Object.seal (không thêm / xóa, vẫn sửa giá trị), Object.preventExtensions (chỉ cấm thêm), và Object.defineProperty để khóa từng thuộc tính.
    2. 
        
  2. Khi nào dùng: cấu hình / hằng số dùng chung; dữ liệu gốc không được phép bị sửa; chặn việc lỡ thêm thuộc tính mới do gõ sai tên.
    3. 
        
  3. Khi nào KHÔNG dùng: freeze chỉ khóa tầng ngoài (nông). Không dùng cho object cần cập nhật thường xuyên. Đây không phải bảo mật thật, người dùng vẫn sửa được qua DevTools, kiểm tra quan trọng phải ở server.
    4. 
        
  4. Tránh xung đột khi web lớn: ở sloppy mode, ghi vào object đã khóa bị bỏ qua âm thầm; chỉ "use strict" mới báo TypeError. Nên freeze cấu hình dùng chung ngay lúc tạo, và freeze đệ quy nếu có object lồng.

 11. Object Prototypes 

    
    
        
  1. Định nghĩa: mỗi object có một prototype (nguyên mẫu). Khi không thấy thuộc tính trong chính nó, JS tìm ngược lên chuỗi prototype cho tới Object.prototype. Method đặt ở prototype được mọi object cùng loại dùng chung.
    2. 
        
  2. Khi nào dùng: chia sẻ method cho nhiều object mà không copy cho từng cái; hiểu cơ chế của class và kế thừa; tạo object kế thừa bằng Object.create(proto).
    3. 
        
  3. Khi nào KHÔNG dùng: không sửa prototype của kiểu có sẵn (Object.prototype, Array.prototype). Không dùng __proto__ trong code mới (dùng Object.getPrototypeOf). Không đặt dữ liệu thay đổi được (mảng, object) lên prototype.
    4. 
        
  4. Tránh xung đột khi web lớn: thêm gì vào Object.prototype sẽ làm mọi for...in của cả trang nhận key lạ và có thể phá thư viện khác. Mảng đặt trên prototype bị mọi object dùng chung, dữ liệu riêng phải khởi tạo trong constructor.
